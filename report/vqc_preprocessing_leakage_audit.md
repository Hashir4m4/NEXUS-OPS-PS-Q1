## 1. Executive Summary & Audit Scope

Prior to the implementation of the Variational Quantum Classifier (VQC) in Milestone 5C, a critical methodological audit of the preprocessing pipeline was conducted. The specific investigation focused on whether the precomputed scaled columns in `data/processed/features_train.csv` could introduce validation-distribution leakage if consumed directly during Leave-One-Record-Out (LORO) cross-validation.

### Core Findings
1. **Direct Usage of Precomputed `*_scaled` Columns in LORO Causes Inter-Patient Leakage:**
   * In `data/processed/features_train.csv`, the six `*_scaled` columns were generated by fitting a `QuantumFeatureScaler` on **all 200 training observations combined** (Records 106 and 119 jointly).
   * LORO cross-validation evaluates patient generalizability across two distinct folds:
     * **Fold 1:** Train on Record 106 ($n=100$), Validate on Record 119 ($n=100$).
     * **Fold 2:** Train on Record 119 ($n=100$), Validate on Record 106 ($n=100$).
   * If an algorithm trains on `*_scaled` features from Record 106, those features were mapped to $[0, \pi]$ using minimum and maximum statistics derived partially from Record 119 (the validation patient). Conversely, Record 119's scaled features reflect extreme values observed in Record 106.
   * This represents a direct violation of inter-patient validation independence, as the validation distribution actively shaped the training feature representation.

2. **Raw Features are Fully Preserved in Both Datasets:**
   * Both `features_train.csv` and `features_test.csv` retain all six raw physiological feature columns (`pre_rr`, `post_rr`, `qrs_rms`, `qrs_duration`, `p2p_amplitude`, `spectral_ratio`).
   * No raw information has been discarded or overwritten.

3. **Precedent in Classical Baseline Pipeline:**
   * The classical baseline module [`src/classical_evaluation.py`](file:///c:/Data/Projects/NEXUS-OPS/NEXUS-OPS/PS-Q1-Biomedical-Classifier/src/classical_evaluation.py#L104-L112) already established the leak-free pattern by extracting raw feature columns and fitting a fresh `QuantumFeatureScaler(clip=True)` dynamically inside each LORO fold.

4. **Empirical Inter-Patient Distribution Shifts are Substantial:**
   * Evaluating fold-isolated scaling reveals that **20.00% of feature values in Fold 1** (54% of beats) and **25.67% of feature values in Fold 2** (89% of beats) exceed the training patient's feature domain and require clipping.
   * Joint pre-scaling artificially compressed both training records into $[0, \pi]$ with **0 clips**, hiding the physiological differences between patient cohorts.

5. **Formal Protocol Separation Required for VQC:**
   * **Protocol A (LORO CV):** Fresh scaler fitted exclusively on each training fold's raw features; validation fold transformed and clipped.
   * **Protocol B (Final Model Benchmark):** Single scaler fitted on all 200 raw training samples (Records 106 + 119); frozen scaler transforms the quarantined test set (Records 200 + 208).

### 2.2 Pipeline Provenance

## 3. Mathematical Mechanism of LORO Distribution Leakage

### 3.1 Scaling Transformation
The `QuantumFeatureScaler` applies an affine transformation mapping continuous feature $x_j$ to rotational angle $\phi_j \in [0, \pi]$:
$$\phi_j = \pi \cdot \frac{x_j - x_{j,\min}}{x_{j,\max} - x_{j,\min}}$$
where the scaling factor is $s_j = \frac{\pi}{x_{j,\max} - x_{j,\min}}$.

### 3.3 Leakage Implications
1. **Contaminated Training Space in Fold 1:**
   In Fold 1 (train on 106, validate on 119), the joint `p2p_amplitude_scaled` maps the maximum voltage to $4.60\text{ mV}$. But Record 106 never experienced an amplitude above $3.65\text{ mV}$. The model is trained on an artificially compressed feature space ($x_{\max} = 4.60$) that was determined by the held-out validation patient!
2. **Severe Distortion in Fold 2:**
   In Fold 2 (train on 119, validate on 106), the joint `spectral_ratio_scaled` uses $x_{\max} = 0.445213$. However, Record 119 has a maximum spectral ratio of only $0.190364$. Training Record 119 on the joint feature causes its entire spectral ratio distribution to occupy only $[0, 1.34\text{ rad}]$, less than half the available $[0, \pi]$ rotation space, solely because of the influence of Record 106.
3. **Artificial Zero-Clipping Illusion:**
   Under joint scaling, exactly zero values in Records 106 and 119 fall outside $[0, \pi]$. But in clinical deployment on a novel subject, inter-patient distribution shifts are pervasive. Using joint scaling in cross-validation masks this reality.

## 5. Formal Preprocessing Protocols for VQC Implementation

To maintain strict scientific hygiene and eliminate any risk of data leakage, the VQC implementation must adhere to two distinct preprocessing protocols:

```
+-----------------------------------------------------------------------------+
|                          RAW DATA: features_train.csv                       |
|                          (Columns: FEATURE_NAMES)                           |
+-----------------------------------------------------------------------------+
                                      |
         +----------------------------+----------------------------+
         |                                                         |
         v                                                         v
[ PROTOCOL A: LORO CV ]                                   [ PROTOCOL B: FINAL BENCHMARK ]
- Fold 1:                                                 - Fit Single Scaler on ALL 200
  * Fit scaler on Rec 106 raw features                      training rows (Rec 106 + 119)
  * Transform Rec 106 (Train) & Rec 119 (Val)             - Transform ALL 200 training rows
- Fold 2:                                                 - Transform Quarantined Test Set
  * Fit scaler on Rec 119 raw features                      (features_test.csv, Rec 200 & 208)
  * Transform Rec 119 (Train) & Rec 106 (Val)             - Evaluate single frozen model
- Clip strictly to [0, pi]                                - Clip strictly to [0, pi]
- ZERO leakage between folds                              - ZERO leakage from test set
```

### 5.1 Protocol A: Leak-Free LORO Cross-Validation Routine
In all cross-validation code (e.g. `src/vqc_evaluation.py`):
1. Load `features_train.csv`.
2. Extract the raw feature columns specified by `FEATURE_NAMES`:
   ```python
   FEATURE_NAMES = [
       "pre_rr", "post_rr", "qrs_rms",
       "qrs_duration", "p2p_amplitude", "spectral_ratio"
   ]
   ```
   **DO NOT** select columns ending with `_scaled`.
3. For each LORO fold:
   ```python
   # Split raw subsets by patient record
   train_sub = df_train[df_train["record_id"] == train_record]
   val_sub = df_train[df_train["record_id"] == val_record]

   # Instantiate a dedicated fresh scaler instance per fold
   fold_scaler = QuantumFeatureScaler(target_min=0.0, target_max=np.pi, clip=True)
   fold_scaler.fit(train_sub[FEATURE_NAMES])

   # Transform subsets using fold-specific parameters
   X_train = fold_scaler.transform(train_sub[FEATURE_NAMES])
   X_val = fold_scaler.transform(val_sub[FEATURE_NAMES])
   y_train = train_sub["label"].to_numpy(dtype=int)
   y_val = val_sub["label"].to_numpy(dtype=int)
   ```
4. Verify that:
   * `np.all((X_train >= 0.0) & (X_train <= np.pi))`
   * `np.all((X_val >= 0.0) & (X_val <= np.pi))`

### 5.2 Protocol B: Final Model Training & Test Benchmark
When training the final model for observational benchmark evaluation on held-out records 200 and 208:
1. Fit a single `QuantumFeatureScaler(target_min=0.0, target_max=np.pi, clip=True)` on the complete 200-sample training dataset using raw features:
   ```python
   final_scaler = QuantumFeatureScaler(target_min=0.0, target_max=np.pi, clip=True)
   final_scaler.fit(df_train[FEATURE_NAMES])

   X_train_full = final_scaler.transform(df_train[FEATURE_NAMES])
   y_train_full = df_train["label"].to_numpy(dtype=int)

   # Load quarantined test set
   df_test = pd.read_csv("data/processed/features_test.csv")
   X_test = final_scaler.transform(df_test[FEATURE_NAMES])
   y_test = df_test["label"].to_numpy(dtype=int)
   ```
2. The precomputed `*_scaled` columns in `features_train.csv` and `features_test.csv` match `X_train_full` and `X_test` exactly. They may only be used for the final full-cohort benchmark, never for LORO.

   * Asserts that `features_train.csv` and `features_test.csv` contain all 6 raw features and that no NaNs or Infs exist.
